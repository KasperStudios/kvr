# Окна рабочего стола хоста в KVR: архитектура

Статус: **решения приняты, D1 написан** (`CHANGELOG.md` → 0014, код в `native/kvr-desktopd/` и `desktop/`).
Свой код, без WaylandCraft и без форков.

## Решения Создателя (зафиксировано)

| Вопрос | Решение |
|---|---|
| **Главное требование** | Окна приложений **никогда не появляются на настоящем рабочем столе** и в WM системы — только внутри Minecraft. Linux и Windows |
| ОС Создателя | Arch Linux, Wayland, **niri**; для игроков — ещё Windows |
| Режим | **hosted / headless**: своя мини-композиция. Зеркало уже открытых окон (портал/PipeWire) **не делаем** |
| Демон | **Rust**, `kvr-desktopd` |
| Запуск | мод сам в фоне через `ProcessBuilder`, если включено и есть согласие |
| Безопасность | **окно согласия (GUI)** на скачивание / запуск стороннего бинарника |
| Клавиатура | в Alt-режиме при наведении / фокусе на окно, которое принимает клавиши, ввод захватывается **автоматически** |

### Как это сделано в D1
- **Ссылка для самопроверки «не на рабочем столе»:** у демона нет ни одного бэкенда вывода (ни winit, ни DRM), он не подключается
  к niri. Приложения запускаются с `WAYLAND_DISPLAY` = сокет демона и **без `DISPLAY`** (X11-программа упадёт, а не выскочит
  через XWayland niri), в **частной D-Bus сессии** (`dbus-run-session`): Firefox/GApplication не передадут запуск уже
  открытому экземпляру на рабочем столе, а диалоги файлов портала не всплывут в niri.
- **Кадры:** буферы wl_shm клиента → memcpy в слот общей памяти → мод делает `glTexSubImage2D` прямо из mapped-буфера,
  только по damage, формат BGRA без перестановки. Размер окна задаёт мод → никакого масштабирования.
  Темп — frame callbacks: окно свёрнуто / HUD выкл → приложение вообще не рисует.
- **Ввод:** свои `wl_pointer`/`wl_keyboard` — фокус Minecraft не теряется, работает при полноэкранной игре. ПКМ над
  окном приложения — правый клик в нём (колесо жестов — вне окон приложений).
- **Согласие** привязано к SHA-256 файла (другой файл = новый вопрос). Скачивание — только с закреплённым хешем,
  файл с другим хешем не запускается. Токен сессии — случайный, только через окружение процесса.

### Windows без окон на рабочем столе (D5) — варианты
Композитора, который можно подменить, в Windows нет, поэтому «скрытость» достигается иначе:

| Вариант | Видно на рабочем столе | Захват | Ввод | Оценка |
|---|---|---|---|---|
| **A. Отдельный Win32-desktop** (`CreateDesktop` + `STARTUPINFO.lpDesktop`) | нет, другой desktop-объект | `PrintWindow(PW_RENDERFULLCONTENT)` в нашем потоке на том же desktop | `PostMessage(WM_*)` в HWND, фокус игры цел | основной: чисто, без драйверов. GPU-приложения (Chromium) иногда дают чёрный кадр → `--disable-gpu`; raw-input игры не управляются |
| B. Виртуальный монитор (Indirect Display Driver) | нет, отдельный «экран» | Desktop Duplication / WGC, GPU | `SendInput` двигает настоящий курсор | подписанный драйвер + установка с правами админа — тяжело, против идеи «один бинарник» |
| C. Окно за пределами экрана + `WS_EX_TOOLWINDOW` + WGC | формально да (Alt+Tab, панель задач у части программ) | WGC | `PostMessage` | запасной, требование нарушается — не берём |

**Решение для D5: A** (тот же протокол, та же общая память; канал управления — AF_UNIX, есть в Windows 10 1803+).

## Ниже — исходный разбор вариантов (до решений), для истории

## 0. С чего начинаем: что уже есть в 0013 и где оно упрётся

Сейчас в 0013 стоит заглушка: TCP `127.0.0.1:47800`, кадры `KVRF w h RGBA` целиком, ввод строками JSON,
кадр заливается в `DynamicTexture` через `setPixelRGBA` по одному пикселю.

| Узкое место | Цена на 1080p, 30 к/с |
|---|---|
| Сырой RGBA-кадр | 8.3 МБ на кадр, **~250 МБ/с** |
| Сокет: копия ядро → `byte[]` → ещё одна | ×2–3 memcpy, лишний мусор для GC (кадр 8 МБ на каждый кадр) |
| `setPixelRGBA` в цикле: 2 млн вызовов на кадр | **десятки мс на кадр** на потоке рендера — главный тормоз |
| Шлём весь кадр, даже если мигнул только курсор | 95% трафика впустую |
| 1080p для окна 480×300 GUI px (на 2× = 960×600) | 3.6× лишних пикселей |

Вывод: **дорого не само чтение сокета, а лишние пиксели и попиксельная заливка**. Архитектура ниже убирает все пять пунктов.

## 1. Захват кадров на хосте

### Linux / Wayland (основная цель)
| Вариант | Окно целиком (даже перекрытое) | Нужно разрешение | Нагрузка | Где работает |
|---|---|---|---|---|
| **A. xdg-desktop-portal ScreenCast + PipeWire** | да (`SourceType = WINDOW`) | диалог выбора окна один раз, дальше `restore_token` (`persist_mode = 2`) | memfd (CPU) или **DMA-BUF** (GPU, без копий), есть метаданные **damage** и **курсора** | GNOME, KDE, Hyprland; у wlroots-портала исторически только целые мониторы |
| B. `ext-image-copy-capture-v1` + `ext-foreign-toplevel-image-capture-source-v1` | да | нет (доверенный клиент) | shm или dmabuf, damage | новые wlroots/Sway, частично Hyprland (у Hyprland ещё `hyprland-toplevel-export-v1`) |
| C. `wlr-screencopy` | **нет**, только монитор | нет | shm/dmabuf | wlroots; окна пришлось бы вырезать самим — плохо |
| **D. Своя мини-композиция (hosted)** | да, мы владеем буферами | не нужно | идеально: буферы клиента у нас, damage из `wl_surface.damage` | везде, где можно запустить программу; **только для окон, запущенных «в KVR»** |

### Linux / X11 (запасной путь)
- **XComposite** (`XCompositeRedirectWindow`): окно рисуется в собственный pixmap, даже если перекрыто.
  Читаем pixmap через **XShm** (`XShmGetImage`), **XDamage** сообщает, что изменилось. Просто, дёшево, без диалогов.
- Крейт `x11rb`. Для GPU-пути есть `GLX_EXT_texture_from_pixmap`, но нам он не нужен (см. раздел 2).

### Windows (если понадобится)
- **Windows.Graphics.Capture** (`CreateForWindow(HWND)`): отдельное окно, кадры текстурами D3D11, на Win11 22H2+ есть
  dirty regions, жёлтую рамку можно убрать (`IsBorderRequired = false`, Win11).
  Дальше копия в staging-текстуру → Map → общая память.
- DXGI Desktop Duplication захватывает только монитор, не берём.

### macOS (последним)
- **ScreenCaptureKit**: `SCStream` с `SCContentFilter` на конкретное окно, кадры в IOSurface. Нужно разрешение Screen Recording.

**Предложение:** Linux = **A** (уже открытые окна) + **D** (приложения, запущенные в KVR) + X11 через XComposite.
Windows и macOS — позже, как отдельные бэкенды того же демона.

## 2. Доставка пикселей в JVM

| Вариант | Копий до GPU | Плюсы | Минусы |
|---|---|---|---|
| TCP loopback (как сейчас) | 3–4 | везде работает | лишние копии, к порту может подключиться любой локальный процесс, конфликты портов |
| Unix domain socket (Java 16+ `UnixDomainSocketAddress`, есть и в Windows 10 1803+) | 2–3 | права файла (только наш пользователь), без портов | пиксели всё равно идут через ядро |
| **Общая память + UDS для управления** | **1** (демон → общий буфер → `glTexSubImage2D`) | минимум копий, ноль мусора в JVM | чуть сложнее протокол (слоты и подтверждения) |
| DMA-BUF прямо в GL-контекст Minecraft | 0 | идеал | Minecraft живёт на GLX/WGL, а импорт dmabuf — это EGL; плюс передача FD в JVM без JNI невозможна. Сейчас нереально |

**Предложение: управление по UDS, пиксели через общую память с тройной буферизацией.**
- Демон создаёт файл `$XDG_RUNTIME_DIR/kvr/<stream>.buf` (на Windows — временный файл в `%LOCALAPPDATA%\kvr\`), мод мапит его через
  `FileChannel.map` → прямой `MappedByteBuffer`. Это работает на Java 17 и 21, без FFM и без JNI.
- Раскладка: заголовок (magic, версия, w, h, stride, формат, номер кадра) + **3 слота**. Демон пишет в свободный слот и
  шлёт по UDS `FRAME(слот, seq, damage-прямоугольники)`, мод заливает и отвечает `ACK(слот)`. **Обратное давление встроено**:
  нет свободного слота → демон пропускает кадр, очередь никогда не растёт.
- **Заливка в GPU:**
  - этап 1: `MemoryUtil.memCopy` из mapped-буфера в указатель `NativeImage`, затем `upload()` — один memcpy на кадр
    вместо 2 млн вызовов (≈0.3 мс на 960×600);
  - этап 2: свой GL-путь — PBO + `glTexSubImage2D` **только по damage-прямоугольникам**, формат `GL_BGRA` без перестановки байтов.
    Версионные различия (1.21.5+ `GpuTexture`) — в `RenderCompat`, как и сейчас.
- **Размер:** мод сообщает демону реальный размер окна в пикселях текстуры (GUI px × 2) — демон масштабирует при захвате
  (PipeWire/WGC умеют). В hosted-режиме ещё лучше: просим приложение **само** отрисоваться в этом размере через `xdg_toplevel.configure`.
- **Частота:** мод шлёт желаемую частоту для каждого окна — в фокусе 60, видно 30, далеко 10, свёрнуто или HUD выкл 0.
- **Курсор** идёт отдельными метаданными (позиция и форма). Движение мыши не перерисовывает кадр, курсор рисуем мы поверх окна.

Бюджет (оценка): 960×600 @30 с damage — типично **5–20 МБ/с** вместо 250; на потоке рендера < 1 мс на окно.

## 3. Обратный ввод

Главная засада: в режиме зеркала ввод уходит в настоящий рабочий стол. Клик **переводит фокус ОС** на то окно, Minecraft
теряет фокус: отпускается мышь, игра встаёт на паузу. Поэтому способы сильно различаются.

| Способ | Фокус Minecraft | Перекрытое окно | Права | Оценка |
|---|---|---|---|---|
| Portal RemoteDesktop (та же сессия, что ScreenCast): `NotifyPointerMotionAbsolute(stream, x, y)`, `…Button`, `…Axis`, `…KeyboardKeycode`; новее — `ConnectToEIS` (**libei**) | теряется | композитор поднимает окно | диалог портала | правильный способ для зеркала на Wayland; GNOME 46+ / KDE 6.1+ |
| uinput (виртуальная мышь и клавиатура) | теряется | нет, только видимое | правило udev | грубо, не берём |
| X11 XTest | теряется | нет | нет | запасной путь для X11 |
| X11 `XSendEvent` в окно | не теряется | да | нет | многие программы игнорируют синтетические события |
| Windows `SendInput` / `PostMessage(HWND, WM_*)` | `SendInput` теряет, `PostMessage` нет | `PostMessage` — да | нет | `PostMessage` не понимают Chromium и игры (raw input) |
| **Hosted: свои `wl_pointer` / `wl_keyboard`** | **не теряется** | да (окно живёт только у нас) | нет | **идеально** |

Смягчения для режима зеркала: `pauseOnLostFocus = false`, после серии кликов демон возвращает фокус окну Minecraft.
Где это возможно — KWin scripting, Hyprland IPC, X11 `_NET_ACTIVE_WINDOW`; GNOME так не умеет.

**Клавиатура со стороны мода.** Сейчас 0013 открывает `TextInputScreen` и шлёт готовую строку — для рабочего стола мало.
Нужен **режим захвата клавиатуры**: клик по окну рабочего стола → прозрачный экран-захват. Он шлёт каждое нажатие и
отпускание (GLFW key, **scancode**, модификаторы) и `charTyped`. Выход — удержание Esc 1 с.
На Linux scancode GLFW = X keycode = evdev + 8: демон отдаёт evdev-код в portal/libei или `wl_keyboard` с нашей xkb-раскладкой
(us + ru, переключение по модификатору как в ОС).

Мышь: абсолютные координаты в пикселях кадра, кнопки как Linux `BTN_*`, скролл в единицах v120 (плавный тачпад тоже).

## 4. Демон `kvr-desktopd`

**Язык — Rust.**
- Разбираем данные из чужих процессов и буферы композитора: безопасность памяти здесь важна.
- Готовые крейты: `pipewire`, `ashpd` (порталы), `smithay` (своя композиция), `x11rb`, `reis` (libei), `windows` (WGC),
  `screencapturekit`.
- Один статический бинарник, кросс-компиляция.

Почему не другие:
- C — те же библиотеки нативно, но больше риска и дольше ревью.
- Python — GIL, задержки, упаковка и копии на каждом кадре; для 30–60 к/с не годится.

```
kvr-desktopd
├─ ipc/        UDS-сервер, протокол v2, токен, общая память (слоты)
├─ capture/    trait CaptureSource { next_frame() -> Frame{slot, damage}, cursor(), resize() }
│   ├─ portal_pipewire.rs   (Wayland: зеркало уже открытых окон)
│   ├─ x11_composite.rs     (X11)
│   ├─ hosted/              (Smithay: мини-композиция, приложения «в KVR»)
│   └─ wgc.rs / sck.rs      (Windows / macOS, позже)
├─ input/      trait InputSink { pointer(), button(), axis(), key() }  → portal/libei | xtest | hosted | sendinput
└─ scale/      масштабирование и перестановка BGRx→RGBA (SIMD), учёт damage
```
- Модель процесса: один демон на пользователя, много потоков-«стримов» (по одному на окно KVR).
  - Запуск: мод сам стартует демон через `ProcessBuilder`, если в `kvr-client.toml` указан `host_desktop_daemon = "/path"`,
    иначе подключается к уже работающему (systemd user unit).
  - Мод закрылся → демон закрывает стримы; через 60 с простоя выходит сам.
- Hosted-режим: `kvr-desktopd launch firefox` → запуск с `WAYLAND_DISPLAY=kvr-0` (+ Xwayland для X11-программ через Smithay).
  Окно приложения = окно KVR 1:1: размер задаёт мод, ввод без потери фокуса.
  - Минус: только программы, запущенные из KVR. Уже открытое окно браузера так не захватить — для него режим зеркала.

## 5. Протокол v2 (набросок)

Сообщение = `u16 type, u16 flags, u32 len, payload` (little-endian). Пиксели в сокет не идут никогда.

| Мод → демон | Демон → мод |
|---|---|
| `HELLO{ver, token, caps}` | `HELLO_OK{ver, caps: mirror/hosted/x11/input}` |
| `LIST` — окна для выбора (зеркало без портала: X11/hosted) | `WINDOWS[{id, title, app_id}]` |
| `OPEN{mode: pick/portal/window_id/launch, arg}` | `STREAM{id, shm_path, slots, w, h, stride, format}` |
| `CONFIGURE{id, w, h, fps, visible}` | `RESIZED{id, w, h, stride}` (пересоздание буфера) |
| `ACK{id, slot}` | `FRAME{id, slot, seq, damage[≤16 rect]}` |
| `INPUT{id, pointer/button/axis/key/text}` | `CURSOR{id, x, y, visible, shape_id}` |
| `CLOSE{id}` | `CLOSED{id, reason}` |

- **Безопасность:**
  - сокет в `$XDG_RUNTIME_DIR/kvr/` (права 0700) + токен из файла 0600 → чужие пользователи и процессы не подключатся;
  - пиксели не покидают ПК: на сервер Minecraft ничего не уходит, в меню окна «Публично» для рабочего стола неактивно (0013);
  - серверный флаг `enable_host_desktop_windows` остаётся.
